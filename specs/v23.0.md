# Especificaciones v23.0 (Estabilización y Arquitectura Base)

## Sprint 0: Auditoría y Preparación de Arquitectura
- Refactorización de componentes (separación de UI y lógica).
- Integración de estado global o mejora en el paso de propiedades.
- Reestructuración de carpetas (`/specs`, `/components`, `/hooks`, `/utils`).
- Eliminación de código no utilizado o hardcodeado.
- *Ninguna funcionalidad nueva. Diseño visual intacto.*

## Sprint 1: Configuración Institucional
- Primera pantalla del sistema.
- Gestión de datos base: Institución, Departamento, Coordinación, Portal, Correo.
- Gestión de identidad: Color principal, Color secundario, Tema.
- Gestión de logos institucionales y firmas.
- Persistencia de esta configuración para todo el sistema.

## Sprint 2: Biblioteca de Recursos
- Gestión centralizada de archivos multimedia.
- Categorías: Logos, Escudos, Fachadas, Firmas, Iconos, Fondos.
- Subida de archivos y persistencia (local/storage).
- Integración con el constructor (selección directa desde la biblioteca).

## Sprint 3: Plantillas Base
- Creación de plantillas predefinidas: Cursos, Diplomados, Convocatorias, Reconocimientos, Eventos, Avisos.
- Sistema de carga rápida de plantillas al editor.

## Principios de Desarrollo
Todo nuevo desarrollo debe ser:
1. **Reutilizable:** Componentes que puedan usarse en diferentes partes del sistema.
2. **Configurable:** Propiedades dinámicas (color, icono, texto, tamaño, borde, enlace).
3. **Modular:** Bajo acoplamiento.
4. **Independiente:** Funcional por sí mismo.
